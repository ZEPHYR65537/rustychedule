# 任务、多模型偏序与额度的数学定义

本文对应 v0.1 的实际实现，修改规划器时必须同时更新本文及相关测试。这里定义的是资源排程和估计，不把不同模型的 token 当成可交换货币，也不声称 token 消耗能证明任务成果。

## 1. 三个分离的账本

任务集合记为 $T$，模型集合记为 $M$。

1. **工作账本**：任务的手动完成比例 $p_t\in[0,1]$、剩余分钟数 $h_t$、基准输入/输出 token 估计 $E_t^I,E_t^O$。
2. **消耗账本**：每次实际使用某模型的输入、输出、缓存、费用与额度单位。永久保留，撤销使用 tombstone。
3. **预留账本**：还没有消耗、但已经分给某任务/模型的原始 token 预算 $B_{tm}^I,B_{tm}^O$。

**禁止使用“实际 token / 预算 token”推导完成比例。** 失败的推理、重试和探索可能消耗很多 token 而没有推进任务。修改进度和记用量可以在同一 CLI 操作中完成，但二者仍是独立字段。

各模型的额度组成向量 $(A_m)_{m\in M}$，不是一个可以自由转移的标量总余额。即使两边单位名称都叫 token，模型 A 的余额也不能支付模型 B 的使用。

## 2. 任务排序与前置关系

用户指定重要性 $I_t\in\{1,\ldots,5\}$、基础紧迫性 $U_t$。紧迫性的截止时间下界为：到期 24 小时内为 5，72 小时内为 4，168 小时内为 3，其余为 1；最终使用二者最大值。已经逾期也属于最高紧迫性。

实现的基础优先分为：

$$S_t=12I_t+8U_t^{\mathrm{effective}}+15\mathbf{1}_{\mathrm{overdue}}+5\mathbf{1}_{\mathrm{doing}}.$$

依赖图必须无环。若 $a$ 是 $t$ 的前置任务，则 $a$ 的规划分至少为 $t$ 的规划分；沿依赖边反复传播直至稳定。仅在前置已经完成、或在当前计划中先安排时，任务才进入候选。

候选按传播后的分数降序、截止时间升序（无截止放后）、ID 升序排列。单次计划的分钟约束为：

$$\sum_{t\text{ 被安排}}h_t\le H.$$

`blocked` 不参与排程，但其未用预算在普通模式仍保留。日程从当前时间连续排起，未建模休息、并行执行或日历空档。前置关系表示执行顺序，不会提前把任务状态写成已完成。

## 3. 硬约束与偏序是不同对象

任务可用模型集合：

$$F_t=\{m:\operatorname{enabled}(m),\ c_m\ge c_t^{\min},\ m\in L_t\},$$

其中 $L_t$ 省略时为全体模型；能力等级是用户自定义的 1–5 级筛选量。跨领域能力不能完整地用一个数表达，领域限制应通过允许列表和任务专属偏序表达。

用户提供的边 $a\succ_t b$ 表示“对任务 $t$，更偏好 $a$”。传递闭包必须是严格偏序：不可自反、不可有环、有传递性。若没有 $a\succ_t b$ 也没有 $b\succ_t a$，二者互不可比。**不把名称、能力分或价格偷偷加入用户偏序。**

给定本轮可实际承担工作的候选 $C_t\subseteq F_t$，先求极大元：

$$\operatorname{Max}_t(C_t)=\{m\in C_t:\nexists n\in C_t,\ n\succ_t m\}.$$

只在极大元之间用确定性策略破平局：完成当前全部剩余需求的估算费用升序、能力等级升序、模型名升序。该破平局仅是运行策略，不新增偏序关系。如果更优模型不可用或额度耗尽，则后继模型可以成为可行集中的极大元。

传递性仍经过不可用模型传播。例如 $A\succ B\succ C$，即使 B 停用，只要 A 可行，仍不能先选 C。

## 4. 降级时换算工作，而非挪用余额

为每个任务/模型设置倍率 $\rho_{tm}\in[0.01,100]$，默认为 1。它表示该模型完成同样工作所需 token 相对于任务基准估计的倍率。倍率由用户估计，不是服务商 token 的兑换率，也不是模型能力证明。上下文交接、额外验证等开销应包含在估计中。

剩余基准需求为：

$$R_t^d=E_t^d(1-p_t),\qquad d\in\{I,O\}.$$

保留预算模式先扣除现有有效预留覆盖的基准需求：

$$D_t^d=\max\left(0,R_t^d-\sum_m\frac{B_{tm}^d}{\rho_{tm}}\right).$$

注意这里除以倍率只是将**同一个任务的估计工作覆盖量**归一化，绝没有把一个模型的额度转账给另一个模型。真实费用、配额扣费、用量报表仍按原模型记账。

将当前剩余工作的比例 $f\in[0,1]$ 分给模型 $m$ 时，预留：

$$x_{tm}^d=\left\lceil\rho_{tm}D_t^d f\right\rceil.$$

随后逐维减少 $D_t^d\leftarrow\max(0,D_t^d-x_{tm}^d/\rho_{tm})$。向上取整可能有不足一个 token 的富余，这是可接受的保守预留。

### 具体例子

某任务剩余基准需求为输入 800、输出 200。偏好 $A\succ B$，$\rho_{tA}=1$，$\rho_{tB}=2$；A 当前可新分配 500 token，B 还有 2000 token。

1. A 承担一半，预留输入 400、输出 100，耗尽 A 可用的 500。
2. 尚余基准输入 400、输出 100；B 需要输入 800、输出 200，预留 1000。
3. 覆盖量分别为 $400+800/2=800$、$100+200/2=200$；每个模型都满足自己的额度约束。

不能把 A 的 500 与 B 的 2000 直接当成 2500 个等效强模型 token。只有任务工作估计可以通过显式倍率做对应。

如果任务能力底线高于 B、允许列表排除了 B，或声明不可分段，则不能按上述方式降级。不可分段时只考虑能完整承担剩余需求的单一模型；有旧预留时必须与旧预留模型一致，否则要求重规划。

## 5. 每模型的多窗口约束

模型 $m$ 的窗口集合为 $W_m$。每个窗口有额度上限 $Q_{mw}$、当前已用量 $U_{mw}$。输入/输出权重 $\alpha_m,\beta_m\ge0$ 且不能同时为零，将原始 token 换成本模型的额度单位：

$$q_m(x^I,x^O)=\alpha_m x^I+\beta_m x^O.$$

同一模型所有窗口都必须满足：

$$U_{mw}+\sum_t q_m(B_{tm}^I+x_{tm}^I,B_{tm}^O+x_{tm}^O)\le Q_{mw},\qquad \forall w\in W_m.$$

额度校准可以使已用值超过上限；这表示现实中的超限记录，不能因此拒绝记录真实用量。规划和普通预算设置则不能继续超配。

保留安全比例 $s\in[0,1)$ 时，可新分配额度为：

$$A_m=\max\left(0,\min_{w\in W_m}\left((1-s)Q_{mw}-U_{mw}-\sum_t q_m(B_{tm}^I,B_{tm}^O)\right)\right).$$

没有窗口的模型按不受限处理并提示。安全余量约束新增预算，不追溯强制缩减已有预留；已有预留超出真实上限则要求重规划。

规划器通过 60 次二分寻找最大的 $f$，**每次都在 token 向上取整之后检查额度**。不能先用浮点比例填满额度再取整，否则可能无意超限。每个模型在同一任务的本轮新增分配中最多使用一次。

## 6. 重新规划的定义

普通 `plan`：保留现有预留，只补足需求；无状态变化时重复 `--commit` 不重复占用预算。

`plan --rebalance`：

1. 复制当前状态。
2. 释放本次项目范围内所有活动任务的未用预算，包括可能暂缓的任务。
3. 保留实际用量、任务进度、额度快照、重置流水和范围外预留。
4. 按同一套约束重新分配 $R_t^d$。
5. 只有指定 `--commit` 才原子保存这个结果。

因此模型 A 已经耗尽时，可把**未完成的工作**重新交给 B，A 已经发生的消耗绝不会转移或抹去。这是本实现“向下兼容”的精确定义；它不承诺低能力模型能完成超出其硬约束的工作。

对于同一任务，只有当试分配能覆盖全部剩余需求时才接纳；否则回滚该任务全部新增分配。整体算法是确定性、可解释的优先级贪心，不是多维背包或整数规划的全局最优解。任务分钟数不随跨模型片段拆分；输出的模型片段属于同一时间段内的协作安排。

## 7. 额度的时间语义

### 自然固定周期

设锚点 $a$、周期 $P$、查询时间 $\tau$。当前窗口起点为：

$$b=a+P\left\lfloor\frac{\tau-a}{P}\right\rfloor.$$

只计算当前周期中的记录；边界时刻的新用量属于新周期。程序离线很久也无需逐次生成自然重置事件。旧余额不结转，任务未用预留会跨重置保留。

### 滚动窗口

计入 $(\tau-P,\tau]$ 内的有效记录，左端点严格排除。每条消耗在记录时间加 $P$ 时释放。只有总量的快照无法恢复各笔年龄，作为一个整体直到 $P$ 后才释放；这是显式标记的保守近似。

### 校准、Tibo 与卡

当前自然窗口内最新的权威校准或手动刷新构成基线，之后再加新用量。记录按 `(时间戳, 单调 ID)` 排序，同一时间的操作也有确定顺序。回填到基线之前的记录进入历史报告但不重复叠加到校准后的额度。

Tibo 是外部随机跳变：观察到时登记对应模型/窗口的 $U_{mw}\leftarrow0$。没有概率分布，也没有预测承诺，因此计划不会包含未来 Tibo 的期望容量。

Reset 卡是有范围、到期时间和次数的离散资源。一次合法登记原子扣减一次机会并刷新目标窗口；范围不匹配、过期、无库存时整个操作失败。自然重置和 Tibo 不消耗卡。

默认额外刷新不改变固定周期相位。显式 `--restart-clock` 才把锚点改为当前时间。刷新清零的是**选定窗口的当前已用量**，不会清除历史实际消耗或未用预留。

## 8. 数值与可解释性边界

- 原始 token 为非负整数；单字段不超过 $10^{12}$。
- 权重、限额、费用为受校验的有限非负浮点数。预算校验允许 $10^{-8}$ 的计算误差，分段搜索本身不增加此余量。
- 倍率、时间和能力都由用户估计；需要交接或验证时应增大 token/分钟估计。
- 当前 $p_t$ 同时缩放输入、输出估计；输入/输出工作完成不同步时可更新整个任务的估计，未来可扩展为分阶段工作包。
- `--no-split` 仅约束本次剩余工作，不要求历史使用过的模型必须相同。
- 不预支未来自然重置；这可能保守地暂缓任务，但不会把尚未发生的随机刷新当作保证。

对应回归测试在 `tests/core.rs`：偏序传递与互不可比、重要任务优先、倍率降级、硬能力底线、整数取整、预算隔离、重规划、自然边界、快照和卡库存。
