# 任务、模型偏序与独立额度的数学定义

对应 v0.2 的实际实现。修改规划、额度或降级语义时，必须同时更新本文与回归测试。估计描述资源需求，不证明任务成果。

## 1. 四个独立概念

任务集合 $T$，模型集合 $M$，额度来源 $S=\{\mathrm{sub},\mathrm{api}\}$。

- 工作：显式进度 $p_t\in[0,1]$、剩余分钟 $h_t$、全任务基准输入/输出估计 $E_t^I,E_t^O$。CLI 的 progress 用 0..100 表示。
- 实际消耗：任务、模型、来源、时间、原始 token；永久留存，错误记录通过 void 标记撤销。
- 未用预留：$B_{tm,s}^I,B_{tm,s}^O$，实际同任务/模型/来源消耗会抵扣预留。
- 复盘：工作分钟、完成内容、收获和下一步；引用一次用量事件，避免双重记账。

实际消耗不能自动换算为进度。重试、探索失败也会耗 token；用户显式更新进度后，剩余需求才改变。

资源是向量 $(A_{m,\mathrm{sub}},A_{m,\mathrm{api}})_{m\in M}$。不同模型余额不能转移；同模型两个来源也分别扣账。不存在“全体模型合计可用 token”这一可供规划消费的标量。

## 2. 任务顺序

重要性 $I_t\in\{1,\ldots,5\}$，基础紧迫性 $U_t\in\{1,\ldots,5\}$。距离截止 24 小时内紧迫性下界为 5，72 小时内为 4，168 小时内为 3，否则为 1；已逾期也为 5。有效紧迫性取用户输入和此下界的最大值。

$$
S_t=12I_t+8U_t^{\mathrm{effective}}+
15\mathbf1_{\mathrm{overdue}}+5\mathbf1_{\mathrm{doing}}.
$$

依赖图必须无环。前置任务继承后继任务的更高分，传播至稳定。候选按继承后的分数降序、截止时间升序、ID 升序排列；前置必须已完成，或已先安排于本计划。blocked 不参与执行，但其预留在普通规划中仍保留。

给定连续可工作分钟 $H$：

$$
\sum_{t\ \mathrm{scheduled}}h_t\le H.
$$

排程从现在顺序执行，暂不建模休息、并行、日历空档、未来周期。分钟数不随模型分段重复计算；用户完成一部分后应同时更新进度和剩余分钟。

## 3. 模型硬约束与偏序

可用模型集合：

$$
F_t=\{m:\mathrm{enabled}(m),\ c_m\ge c_t^{\min},\ m\in L_t\}.
$$

$L_t$ 省略则允许全部。能力 1..5 只是用户定义的筛选尺度，跨领域要求应用允许列表表达。

用户边 $a\succ_t b$ 表示任务更偏好 a。它必须无环、不可自反；选择通过可达性使用其传递闭包。没有任一方向可达时互不可比。任务有专属偏序就整体覆盖全局边；任务偏序为空则继承全局偏序。模型名称没有内置质量排名。

对本轮可行集合 $C_t$ 取极大元：

$$
\mathrm{Max}_t(C_t)=\{m\in C_t:\nexists n\in C_t,\ n\succ_t m\}.
$$

在互不可比极大元中，以当前剩余工作预计原始 token 数升序、能力等级升序、名称升序确定性破平局。这不新增偏序关系，更不以金额排序。传递性经过不可用节点仍成立：若 $A\succ B\succ C$，B 停用不改变 $A\succ C$。

## 4. 各模型订阅与 API 约束

### 订阅

模型 m 的订阅有窗口集合 $W_m$，上限 $\hat Q_{mw}$、已用 $U_{mw}$。标准订阅按输入+输出原始 token，权重均为 1；兼容旧自定义额度单位时：

$$
q_m(x^I,x^O)=\alpha_m x^I+\beta_m x^O.
$$

对每个窗口同时满足：

$$
U_{mw}+\sum_t q_m(B_{tm,\mathrm{sub}}^I+x_{tm,\mathrm{sub}}^I,
B_{tm,\mathrm{sub}}^O+x_{tm,\mathrm{sub}}^O)\le\hat Q_{mw},
\quad \forall w\in W_m.
$$

窗口不是可以累加的余额。周额度和五小时额度共同限制同一模型；选择最紧约束。

安全余量 $r\in[0,1)$ 下，可新增订阅预留：

$$
A_{m,\mathrm{sub}}=
\max\left(0,\min_{w\in W_m}
\left((1-r)\hat Q_{mw}-U_{mw}
-\sum_t q_m(B_{tm,\mathrm{sub}}^I,B_{tm,\mathrm{sub}}^O)\right)\right).
$$

订阅停用时此值为 0。没有窗口和账户配置的旧模型按无限额处理并提示；API-only 账户没有订阅容量。

### API

用户为每个模型单独设置累计 token 上限 $K_m\ge0$。累计有效 API 实际消耗为 $C_m$，API 未用预留为 $R_m^{\mathrm{api}}=\sum_t(B_{tm,\mathrm{api}}^I+B_{tm,\mathrm{api}}^O)$。

$$
A_{m,\mathrm{api}}=\max(0,(1-r)K_m-C_m-R_m^{\mathrm{api}}).
$$

$$
C_m+R_m^{\mathrm{api}}+\sum_t(x_{tm,\mathrm{api}}^I+x_{tm,\mathrm{api}}^O)\le K_m.
$$

API 固定按原始 input+output 计量；cached 已包含于 input。$K_m=0$ 时没有 API 候选，直接寻找可行降级模型。$K_A$ 再大也不能提高 $A_{B,\mathrm{api}}$。top-up 只增加指定模型的 $K_m$，不发生实际购买。

例：$K_A=50000,C_A=12000,R_A^{\mathrm{api}}=8000$，不保留安全余量时还可新增 30000；默认 $r=0.1$ 时为 25000。订阅自然重置、卡、Tibo 都不改变 $K_m,C_m,R_m^{\mathrm{api}}$。

实际记账可超过上限，因为历史事实不应被预算拒绝；新规划不会继续超配。api set 0 会释放该模型未用 API 预算，已用历史保留。

## 5. 来源策略与偏序的组合

每轮候选是 $(m,s)$，必须有至少一个经整数取整后可承担的片段。

1. **subscription-first（默认）**：若有可行订阅候选，只在订阅候选间按模型偏序选；否则在 API 候选间选择。可先降到其他模型的订阅，再考虑强模型 API。
2. **model-first**：在所有来源候选的模型上取偏序极大元；同一个模型优先订阅，耗尽后用其 API。该模型两种来源均不可行才降级。
3. **subscription-only**：API 永不进入候选。

所以“保持模型质量”和“优先已有订阅”是两个明确策略，均受每模型 API 上限约束。偏序与来源策略不是全局最优目标函数；它们定义确定性逐步选择。

不可分段任务先筛掉两个允许来源合计也无法覆盖剩余工作的模型。选定后只能继续使用同模型，订阅不足可以接本模型 API。这是 --no-split 的含义，不是禁止切换额度来源。

## 6. 降级换算工作，不转移余额

用户给出任务/模型倍率 $\rho_{tm}\in[0.01,100]$，默认 1；它表示完成同样工作所需原始 token 相对基准的倍数，不是余额兑换率。

$$
R_t^d=E_t^d(1-p_t),\qquad d\in\{I,O\}.
$$

普通规划先扣除已有未用预留覆盖：

$$
D_t^d=\max\left(0,R_t^d-\sum_{m,s}\frac{B_{tm,s}^d}{\rho_{tm}}\right).
$$

将当前剩余工作比例 $f$ 分给 $(m,s)$ 时：

$$
x_{tm,s}^d=\left\lceil\rho_{tm}D_t^d f\right\rceil,
\qquad
D_t^d\leftarrow\max(0,D_t^d-x_{tm,s}^d/\rho_{tm}).
$$

每一步仅减少选定模型与来源的余额；不会把 A 消耗改写为 B 消耗。取整可有不足一个 token 的保守富余。通过 60 次二分搜索，在向上取整后检查所有约束，避免浮点比例填满后再取整导致超限。本轮每个任务的每个模型/来源最多尝试一次。

### 带 API 上限的算例

任务剩余基准输入 800、输出 200；$A\succ B$，$\rho_{tA}=1,\rho_{tB}=2$。采用 model-first，不保留安全余量。A 订阅可新分配 300，A API 上限减实际和预留后为 200，B 订阅可新分配 2000。

| 分配 | 输入/输出 | 本模型本来源消耗 | 覆盖基准工作 |
|---|---|---|---|
| A 订阅 | 240 / 60 | 300 | 30% |
| A API | 160 / 40 | 200 | 20% |
| B 订阅 | 800 / 200 | 1000 | 50% |

基准覆盖输入 $240+160+800/2=800$，输出 $60+40+200/2=200$。每个来源各自守约，没有统一余额。

若 A 的 API 上限为 0，第二行不存在；剩余 70% 工作交给 B，需要 1400 个 B token。若 B 不满足能力底线或允许列表，任务暂缓；不能为了排满计划而降低硬要求。

## 7. 周百分比与估计

服务商只显示百分比 $z\in[0,100]$ 时，配置估计周容量 $\hat Q_{m,\mathrm{week}}$。校准时保存原始 z、时间和当时换算的 used。当前基线按最新容量估计换算：

$$
\hat U_{m,\mathrm{week}}(\tau)=
\frac z{100}\hat Q_{m,\mathrm{week}}
+\sum_{\text{基线后有效订阅使用}}q_m(i,o).
$$

原始百分比不是精确 token 测量。更新容量后，原始 z 不变，当前估计余额重算；之后的已知原始使用不按比例放大。多个历史校准以当前周期最新的权威基线为准，不累加百分比。回填到基线之前的使用进入历史报告，不重复扣当前余额。

标准订阅显示 ~ 估计标识。月续期日是日历提示，与 7 天自然额度窗口独立。不能把续期提示再当作一次额外周重置。本版不学习容量、不输出置信区间。

## 8. 重新规划与失败回滚

普通 plan 保留已有预留，只补不足；状态不变时重复 commit 不重复占额。已预留模型被禁用、不符合新硬约束或超配时暂缓并给出解释。

plan --rebalance：

1. 在状态副本释放本次项目范围活动任务的全部未用预留（包含可能暂缓的任务）。
2. 保留实际用量、显式进度、卡库存、校准、刷新和范围外预留。
3. 按相同顺序与约束重新分配剩余工作。
4. 仅 --commit 保存结果，否则只是预览。

任务只有全部剩余需求可覆盖才接纳，否则回滚该任务的全部新分配。算法是可解释的优先级贪心，不保证最多完成任务数或全局最优品质；重要大任务可能因无法完整安排而暂缓，较小任务可继续。

## 9. 重置时间语义

固定周期锚点 a、周期 P、查询时刻 $\tau$，窗口起点：

$$
b=a+P\left\lfloor\frac{\tau-a}{P}\right\rfloor.
$$

只计算当前周期；边界时刻新用量属于新周期，无需生成自然重置事件。旧未用额度不结转；任务尚未消耗的预留仍保留。

滚动窗口统计 $(\tau-P,\tau]$；左端严格排除。单次使用在时间+P 释放。只有总量的快照无法知道各笔年龄，整体延迟到 P 后释放，显示保守近似。

校准/刷新按 (时间戳, ID) 确定先后。Tibo 只在观察到外部自动刷新后登记，重置选定订阅窗口已用基线；没有概率分布，不预支任何期望额度。

卡是有作用范围、有效期、库存的离散资源。一笔合法登记扣一次机会，再分别刷新目标模型窗口。过期、无库存、不匹配时整笔失败；自然刷新和 Tibo 不扣卡。默认不改变固定周期相位；--restart-clock 才修改为现在起算。

任何订阅刷新都不抹去历史实际消耗、不清除未用预留、不影响 API。

## 10. 数值与建模边界

- 原始 token 为非负整数，单字段最大 $10^{12}$；估计、权重、窗口上限必须有限非负。
- 预算校验允许 $10^{-8}$ 浮点容差；分段搜索先取整再判可行。
- 安全余量只约束新增预留，不强制缩减已存在、未超过真实上限的预留。
- 不预测 Tibo、不预支未来自然周期或未使用的卡。
- 倍率与分钟由用户估计，交接/验证开销应自行计入；尚未分阶段建模。
- 修改窗口锚点会改变当前周期解释，当前系统不提供任意过去时刻的额度回放。
- 对应测试：tests/core.rs、tests/v2.rs；包括偏序、继承、倍率、零 API、来源独立、整数取整、重规划、快照与三类刷新。
