# 设计决策记录

状态：已接受并实现。日期：2026-09-21。目的：保留本次需求澄清，避免后续升级丢失语义。

## ADR-001：模型额度必须独立

**用户明确要求**：“不要把多个模型的额度混在一起，需要分别管理，因为不同任务可能使用不同模型。”

每个模型恰有一个同名额度容器，内含多个限制窗口；数据校验拒绝共享容器和跨模型消费记录。内部 `Pool` 是容器名称，不表示账户共享余额。即使不同模型属于同一供应商也不合并。以后如需账户总上限，必须增加一层独立约束，不能取消模型独立账本，且需要新的需求确认。

## ADR-002：Tibo 是随机外部自动刷新

**用户澄清**：reset 卡是可配置的额外重置机会；Tibo 指直接自动刷新额度，随机性很大。

因此 Tibo 不是库存、不是卡、不是定时任务。它只在用户观察到后登记。自然重置按时间计算；卡有独立库存。默认保留原周期相位，提供显式重启周期选项。

## ADR-003：偏好是任务专属严格偏序

**用户提出**：不同任务对模型有不同偏好，可能指定偏序关系。

使用 DAG 边及传递可达性，不用唯一全局模型排名替代。互不可比保持互不可比；破平局是透明运行策略。模型名称没有内置品质排序。能力底线、允许列表是硬约束，偏序是硬约束内的选择策略。

## ADR-004：降级切换的是剩余工作

**用户提出**：重要任务先用更强模型，用光后转用其他模型，原额度规划须向下兼容，并在数学上理清。

用任务/模型倍率转换基准工作需求与该模型的原始 token 预算。允许分段也允许禁止分段。重新规划释放未用预留，保留已发生消耗；不移动历史消耗、不合并模型余额。具体约束见 `MATHEMATICS.md`。

## ADR-005：实际 token 不等于任务进度

失败尝试、重复上下文、无成果的探索都会耗费 token。进度必须显式更新，默认不从消耗推断。预算抵扣与任务进度分别计算。修改绝对进度不会重写历史使用流水。

## ADR-006：规划可解释、可预览、可原子提交

采用带依赖优先级继承的贪心排程，不声称全局最优。当前额度按最紧的窗口约束；不预支未来自然重置、未知 Tibo、尚未兑换的卡。失败的任务试分配整体回滚。默认预览，`--commit` 保存；`--rebalance` 是显式的预算重分配语义。范围外预算仍受保护。

## ADR-007：文件优先，运行时完全离线

首版使用带版本号的 JSON，便于导出、检查、备份和迁移。目录锁保证单次命令的读改写互斥；同目录临时文件、同步、原子替换；保存前保留前一版本。无模型 API 密钥、自动登录、遥测或后台守护进程。后续自动采集接入统一流水入口，不直接修改累计计数。

## ADR-008：持久化范围与产品限制

使用流水、校准和刷新事件保留额度历史；预算替换保留已释放记录。任务编辑与配置编辑保存当前状态及上一文件版本，**不是**完整事件溯源系统。未来完整审计必须新增明确的变更事件与迁移方案，不能宣称现有字段可还原任意过去状态。

`--restart-clock` 修改当前配置锚点，当前额度查询使用新锚点；不提供历史任意时刻的额度回放。历史 token/费用报告来自原始流水，不受相位修改影响。

## 后续变更要求

1. 先确认是否触及以上用户约束。
2. 变更数学语义时先更新模型与算例，再更新实现和回归测试。
3. 不兼容数据变更提升版本并提供迁移，先备份再转换。
4. 供应商规则、价格和型号名单都可能变化，不把本地示例伪装成官方套餐。
5. 本仓库为 `https://github.com/ZEPHYR65537/rustychedule.git`，CLI 命令名保留为 `tongchou`。
