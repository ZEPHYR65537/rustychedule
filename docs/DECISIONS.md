# 设计决策记录

状态：已接受并实现；后续 ADR 明确覆盖旧版约束。日期：2026-09-21。目的：保留本次需求澄清，避免后续升级丢失语义。

v0.3 项目管理以 ADR-017 至 ADR-021 为准，覆盖 ADR-012/013 中仅适用于旧 hub 的组织与合并限制。数学约束 ADR-001 至 ADR-011 不变。

## ADR-001：模型额度必须独立

**用户明确要求**：“不要把多个模型的额度混在一起，需要分别管理，因为不同任务可能使用不同模型。”

每个模型恰有一个同名额度容器，内含多个限制窗口；数据校验拒绝共享容器和跨模型消费记录。内部 `Pool` 是容器名称，不表示账户共享余额。即使不同模型属于同一供应商也不合并。以后如需账户总上限，必须增加一层独立约束，不能取消模型独立账本，且需要新的需求确认。

## ADR-002：Tibo 是随机外部自动刷新

**用户澄清**：reset 卡是可配置的额外重置机会；Tibo 指直接自动刷新额度，随机性很大。

因此 Tibo 不是库存、不是卡、不是定时任务。它只在用户观察到后登记。自然重置按时间计算；卡有独立库存。默认保留原周期相位，提供显式重启周期选项。

## ADR-003：偏好是任务专属严格偏序

**用户提出**：不同任务对模型有不同偏好，可能指定偏序关系。

使用 DAG 边及传递可达性，不用唯一全局模型排名替代。互不可比保持互不可比；破平局是透明运行策略。模型名称没有内置品质排序。能力底线、允许列表是硬约束，偏序是硬约束内的选择策略。

## ADR-004：降级切换的是剩余工作

**用户提出**：重要任务先用更强模型，用光后转用其他模型，原额度规划须向下兼容，并在数学上理清。

用任务/模型倍率转换基准工作需求与该模型的原始 token 预算。允许分段也允许禁止分段。重新规划释放未用预留，保留已发生消耗；不移动历史消耗、不合并模型余额。具体约束见 `MATHEMATICS.md`。

## ADR-005：实际 token 不等于任务进度

失败尝试、重复上下文、无成果的探索都会耗费 token。进度必须显式更新，默认不从消耗推断。预算抵扣与任务进度分别计算。修改绝对进度不会重写历史使用流水。

## ADR-006：规划可解释、可预览、可原子提交

采用带依赖优先级继承的贪心排程，不声称全局最优。当前额度按最紧的窗口约束；不预支未来自然重置、未知 Tibo、尚未兑换的卡。失败的任务试分配整体回滚。默认预览，`--commit` 保存；`--rebalance` 是显式的预算重分配语义。范围外预算仍受保护。

## ADR-007：文件优先，日常离线（联网边界由 ADR-012 扩展）

首版使用带版本号的 JSON，便于导出、检查、备份和迁移。目录锁保证单次命令的读改写互斥；同目录临时文件、同步、原子替换；保存前保留前一版本。无模型 API 密钥、自动登录、遥测或后台守护进程。后续自动采集接入统一流水入口，不直接修改累计计数。

## ADR-008：持久化范围与产品限制

使用流水、校准和刷新事件保留额度历史；预算替换保留已释放记录。任务编辑与配置编辑保存当前状态及上一文件版本，**不是**完整事件溯源系统。未来完整审计必须新增明确的变更事件与迁移方案，不能宣称现有字段可还原任意过去状态。

`--restart-clock` 修改当前配置锚点，当前额度查询使用新锚点；不提供历史任意时刻的额度回放。历史 token 报告来自原始流水，不受相位修改影响。

## 后续变更要求

1. 先确认是否触及以上用户约束。
2. 变更数学语义时先更新模型与算例，再更新实现和回归测试。
3. 不兼容数据变更提升版本并提供迁移，先备份再转换。
4. 供应商额度规则和型号名单都可能变化，不把本地示例伪装成官方套餐。
5. 本仓库为 `https://github.com/ZEPHYR65537/rustychedule.git`，主命令改为 `schedule`，短名 `tc`，`tongchou` 仅作兼容入口。


## ADR-009：只管理用量，彻底移除费用

用户最终明确“不需要估计或者管理费用，只管理用量”。v0.2 移除价格、货币、cost、月费等字段与参数；保留订阅套餐文字和可选续期日仅作提醒。旧数据迁移保留用量，舍弃被移除的费用字段。计划破平局使用预计 token，不再使用估算费用。

## ADR-010：API 购买上限按模型独立、零值硬禁用

每个模型维护自己的累计 api_token_limit。可新增量是上限减本模型累计实际 API 使用、未用 API 预留及规划安全余量，绝不把不同模型的购买额度合并。上限为 0 时不安排 API，且释放其旧 API 未用预留；正数也不能超过剩余上限。上限不会随订阅刷新自动补充。实际超限事实可记录，未来规划受约束。

## ADR-011：来源策略独立于模型偏序

全局偏序提供常用默认值；任务非空偏序整体覆盖全局。subscription-first 为默认，model-first 为“优先保持用户指定的模型质量”，subscription-only 禁止 API。在 model-first 下，本模型订阅不足才用自己的 API，再不足则降级。不可分段限制模型，不限制同模型的额度来源切换。

## ADR-012：中心工作空间与原代码仓库并存

用户倾向“已有代码仓库则只管记忆、维护原仓库列表”。因此已有远程的项目采用 reference，中心存状态、任务、复盘、上下文和长期记忆；代码留原仓库。本地无远程项目可选择 snapshot，提交后的 HEAD 历史以 bundle 保存。绝对路径留本机 local.json，换机器 bind/checkout。

这扩展 ADR-007 的首版完全离线边界：日常操作离线，显式 hub push/pull/clone 和 project checkout 可以通过 Git 联网。复用 Git 认证，不引入模型 API key。GitHub 账号映射默认仓库地址，用户预建私有仓库；不是自动登录或自动发现任意账号所有仓库。

## ADR-013：并发冲突宁可明确停止

本版保持数值 ID 兼容，采用单写端设备交接，基线指纹检测本机/远端双边修改，只允许 Git 快进，不自动文本合并状态、不强制 push。--replace 是用户显式选择远端业务状态，先保留本机 .bak；镜像脏文件仍不覆盖。未来合并必须先引入全局唯一 ID、事件幂等与实体版本。

## ADR-014：百分比保留观测，token 容量承认估计

订阅 week 窗口 limit 代表估计周容量；Event.observed_percent 保留原面板值，used 保留登记时换算量。容量修正会重新换算当前基线，不改原始百分比。未来新增估计版本/置信度和预测器，本版不自动学习。月续期提示与周自然刷新独立，不将其当作额外额度。

## ADR-015：复盘与使用流水关联

WorkSession 保存实际时间、完成内容、收获、下一步，并可引用一条使用事件。一次 work log 不重复扣账。进度需用户显式输入，复盘撤销不反推进度。任务当前字段与配置尚非完整审计，不夸大为可任意回放的事件溯源系统。

## ADR-016：主命令 schedule，短命令 tc

用户不希望输入长拼音。Rust package/library 和主可执行名改为 schedule，提供 tc 相同入口，旧 tongchou 保留兼容。数据目录优先 schedule，若仅存在旧默认数据则复用；环境变量优先 SCHEDULE_DATA，兼容 TONGCHOU_DATA。

## ADR-017：逻辑任务与 agent 项目独立

逻辑任务是用户要完成的工作，包括手工工作。agent 项目是平台工作容器，可包含聊天、多文件夹、多仓库。两者及聊天到任务采用可选多对多关联。文件夹不自动成为逻辑任务。整理、合并、拆分 agent 项目不改变进度、历史用量或预留。保留旧 Task.project 为规划标签，不重新解释为 agent 身份。

## ADR-018：唯一 sync 仓库与两种仓库定位

无独立 Git 仓库的登记目录整体纳管，排除缓存等内容；不要求先识别记忆，也不为这些目录分别创建 Git。独立代码仓库仅存索引：可携带 remote，或者机器身份＋本地路径。纯本地路径是用户明确要求共享的元信息，不再一律仅本机保存。机器稳定 ID 与可改别名分开；新设备克隆 hub 不复制当前设备身份。没有 remote 的代码索引不代表已备份，不能凭空恢复代码。旧 bundle 保留供恢复，新登记不默认产生 bundle。

## ADR-019：Git 原生结构维护

hub 格式升级到 2，使旧 writer 拒绝写入。agent/节点/仓库/机器使用随机 128 位身份，每记录一个可编辑 JSON，正文为普通文件。节点构成无环单父树，仓库可以被多个节点引用。合并默认保留来源分组、作用域和旧项目去向，不自动拼接记忆或改写平台服务端对象。原目录与原仓库不随中央节点移除而删除。

Git 保存历史，CLI 只做轻量结构校验与文件操作。合并先在临时工作树检查文本和结构，失败保留原工作树。逻辑任务账本仍使用 v2 及指纹冲突保护；不能因为 agent 记录可合并而宣称用量账本可任意合并。

## ADR-020：来源基准与选择性正文

中央原生文件直接编辑，采集来源按“上次内容、当前来源、当前中央”比较；双方不同修改不覆盖。来源缺失、未检出、明确删除相互区分。来源删文件默认保留中央副本，显式 prune 才删除未被中央另行修改的文件。目录移动后原来源布局不能静默重建另一套目录，应明确导出新的工作结构。

完整小目录信息常驻，正文可选择项目或节点子树。选择正文不缩小模型预算核算范围。sparse checkout 仅控制工作树；partial clone 是否减少传输取决于服务器与所需对象，不能作为权限隔离。agents-only 不导入/导出本机规划，不过滤已经提交的 Git 历史。

## ADR-021：一次中央迁移与明确能力边界

旧仓库登记转为索引，旧记忆进入“v0.2 待整理资料”，不猜测平台容器归属。规划数据不重编号，旧文件与 bundle 原样备份在 legacy/v02。其他设备跟随同一中央迁移；分叉旧副本应保留后重新 clone，不能各自生成迁移身份。平台内部不可导出的记忆不属于 CLI 已同步内容；当前通过来源链接、文件和显式摘要交接。
