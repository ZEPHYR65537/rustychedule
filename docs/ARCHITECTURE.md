# 架构与数据

## 模块

| 文件 | 职责 |
|---|---|
| `src/domain.rs` | 任务、模型、窗口、预算、卡、流水；验证、额度重建、预算检查 |
| `src/planner.rs` | 依赖与优先级、偏序候选、分段分配、倍率、重规划与提交 |
| `src/cli.rs` | 参数定义、命令事务、手动录入和演示数据 |
| `src/ui.rs` | 中英文等宽表格、四象限、配额条、计划与每日趋势 |
| `src/store.rs` | 本地目录、文件锁、校验、原子写入、备份与导入 |
| `tests/core.rs` | 确定性时间下的领域边界和数学约束回归 |
| `tests/cli.rs` | 调用真实二进制的跨命令流程和失败原子性测试 |

没有供应商网络依赖；只有构建依赖需要从 crates.io 下载。命令运行时不连接网络。

## 文件与事务

数据目录包含 `state.json`、`state.json.bak`、`.lock`。每条命令获取独占文件锁，读取并校验状态。修改在内存完成，校验成功才保存。保存将原文件复制为上一版本，再将同目录已同步的临时文件原子替换为新文件；Unix 额外同步目录。预览不保存。遇到正在使用的数据目录立即返回错误，不无限等待。

文件损坏时普通命令拒绝继续；`import PATH --replace` 是显式恢复入口，会先校验源备份。损坏原件另存为 `state.json.corrupt`，不会覆盖上一份可用的 `.bak`，避免恢复过程意外毁掉唯一可用备份。导出默认拒绝覆盖目标；`--force` 可覆盖。导入是完整替换，不是合并。

## v1 数据字段

- `version`：当前为 1；未知版本拒绝读取。
- `next_id`：单调增长的统一 ID，任务、预算、卡和事件共享；不能假设卡 ID 紧接任务 ID。
- `currency`：统一费用单位，默认 CNY；不自动换汇。
- `tasks`：当前状态、估计、进度、依赖、项目/标签、模型限制、偏序边、倍率。
- `models`：提供方、能力、价格、启用状态、唯一同名额度绑定、输入/输出权重。
- `pools`：与模型一一对应；每个包含多个 `fixed`/`rolling`/`manual` 窗口。
- `budgets`：原始 token 预留及创建时间；被替换/释放后保留 `released=true`。
- `credits`：卡/自定义重置机会、库存、模型/窗口限制、到期时间。
- `events`：`usage`、`snapshot`、`reset`，包含时间、ID、备注、撤销标记。

所有时间保存 UTC RFC3339，显示使用系统本地时区；输入不带时区时按本地解析，夏令时歧义拒绝并要求显式偏移。日期型截止和卡到期按当地 23:59:59；其他纯日期输入按 00:00:00。

价格修改不会重算历史费用；权重修改不会重算已记录的额度单位，但当前未用预算会按新权重估算。`snapshot` 只校准一个窗口，不能推断其他窗口当前数值。累计报表统计原始消费，重置不影响累计记录。

## 自动化扩展入口

首版 `--json` 提供机器可读结果。未来采集器应产生与手动输入相同的事件，加上供应商事件 ID、采集来源和去重键；应支持重试幂等、UTC 时间、独立模型映射和校准事件。未知 token/额度兑换率不能自动臆造，需保留“不确定”或用户校准。

自动化应始终先展示差异，用户授权后才操作真实账号重置；当前 `reset` 仅记本地账。将随机 Tibo 当作观测事件，不擅自写成固定周期。
