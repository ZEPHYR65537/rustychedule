## 使用循环

1. 配置常用模型、订阅估计周容量、准确的下次周重置时间及各模型 API token 上限。
2. 写任务重要性、紧迫性、截止时间、剩余分钟、全任务 token 估计。
3. 全局设置常用偏序；特殊任务用允许列表、能力底线及专属偏序约束。
4. 查看总览和四象限，预览 plan，确认计划后使用 --commit 留出预算。
5. 工作结束用 work log 同时写实际时间、来源、tokens、完成内容、收获、下一步；进度显式输入。
6. 面板显示百分比时 reconcile；突发 Tibo 发生后登记；用过卡后登记卡刷新。
7. 重要模型耗尽或需求变化时 plan --rebalance，解释降级和暂缓原因。
8. 离开机器前 hub push；换机器先 hub pull，重新绑定项目目录后继续。

所有操作均为普通 CLI，不打开图形界面。工具不实际执行模型调用、API 购买或账户重置。

## 额度模型与用户最近澄清

每个模型都是独立账户，含可选订阅与 API 累计允许使用的 token 上限。没有全局购买额度、金额、汇率、价格或费用估计。

订阅保存套餐名称、可选月续期日、启用状态、估计说明；周额度保存在固定 7 天窗口。首次不传 next-reset 则从当前时间锚定，建议以真实面板时间配置。月续期只是提示，不额外刷新周额度。

面板百分比作为原始观测单独保存，estimated weekly tokens 是可修订参数。显示“估计 token 数、估计使用率、原始面板观测”，避免让换算值看起来像服务商测量值。

API set --limit 是累计上界：设为 0 时释放本模型尚未消耗的 API 预留，禁止后续 API 分配；正数时减去本模型历史实际 API 使用和未用预留后才能新分配。默认还有规划安全余量。top-up 增加上界，不对其他模型产生影响。实际使用支持记录超限事实，规划受上界约束。

## 三种策略

默认 subscription-first 适用于优先消耗现有订阅；model-first 适用于重要工作希望继续使用偏好模型；subscription-only 禁止 API。

model-first 的关键顺序是“偏好模型订阅 → 该模型 API 剩余上限 → 降级模型”。这不是“只要强模型有任意付费能力就无限买”。API 为 0 时中间步骤自然消失。偏好模型的两种来源耗尽后，其他模型只能使用自己的订阅和自己的 API 上限。

对互不可比模型，使用预计原始 token、能力、名字确定性破平局，不猜测用户没有声明的偏好。修改策略或偏序后不自动改写已提交预留，使用 rebalance 显式重排。

详见 [数学定义](MATHEMATICS.md)，含分来源不等式和 A→B 算例。

## 三种刷新

| 情形 | 数据与时机 | 对 API 的影响 |
|---|---|---|
| 自然重置 | 固定周期按锚点算当前窗口；滚动窗口按各笔年龄释放 | 无 |
| Reset card | 可登记范围、次数、截止；实际使用后用 credit ID 记录，扣一次机会 | 无 |
| Tibo | 外部不可控的自动刷新，观察到以后登记；不作为库存、不预测未来 | 无 |

刷新不意味着任务进度增加，也不消除历史复盘。额外刷新默认保留自然周相位，服务商实际改变周期时才传 --restart-clock。

## 复盘与长期积累

WorkSession 保存时间、完成内容、收获、下一步，可引用一条用量 Event。一条 work log 带 tokens 时同时创建事件，统计通过引用而不是重复累加。

任务全程 token 估计、显式进度、剩余分钟各自独立。实际消耗可以与估计比较，但工具不自动声称“用了 50% tokens 就完成 50%”。失败探索的经验可以写 learned，完成量写 done。

撤销复盘会撤销它创建的用量事件，但不自动回滚后来可能已更新的任务进度。只撤销用量时，时间和成果记录继续存在。当前任务字段与模型配置只存现值+前一文件备份，不是全变更审计日志。

## 代码留原处，信息统一组织

采用混合注册模式：

- **reference**：已有远程代码仓库，工作空间只存原仓库 URL、项目元信息、任务、上下文和记忆。原代码由原 Git 仓库自己同步。
- **snapshot**：没有远程的本地 Git 项目，将已提交 HEAD 可达历史制作 Git bundle，写入统一工作空间。源仓库不改分支、不自动提交、不移动文件。

注册时检测 origin：可携带 HTTPS/git@ 地址默认 reference，否则默认 snapshot。显式 --mode 可以选择。项目使用稳定 slug，机器上的绝对路径只保留于 local.json。

统一项目视图展示分支、HEAD、改动文件数、关联活动任务和未绑定错误。project diff 提供 Git 改动统计及文件清单；上下文、长期记忆使用 project note，任务自己的上下文用 task --note。

中央仓库按 projects/<name> 和 tasks/<id> 组织，自动生成 README 索引。便携 state.json 为唯一权威导入来源，其他 JSON/Markdown 为浏览视图。不要在 GitHub 修改派生 Markdown 来期待自动回写；通过 CLI 更新。

### 换设备

已有本地代码用 project bind，尚无本地代码用 project checkout。reference 从原 URL 克隆；snapshot 从校验后的 bundle 恢复到新目录。旧设备未推送到原仓库的 reference 代码不会跟随 hub 同步。

snapshot 只携带 HEAD 历史；未提交/忽略文件不在其中。当前拒绝含子模块的快照；LFS 对象不包含在 Git bundle 内。快照限 90 MiB，适合小型本地项目，大项目使用原代码仓库。包括历史的 bundle 仍需用户按自己的项目内容管理，常见敏感文件名检查不是完整历史秘密扫描。

Git bundle 是 Git 原生的对象/引用运输格式，可被 clone 使用；不等于工作目录压缩包。[Git 官方说明](https://git-scm.com/docs/git-bundle)。90 MiB 是本工具的保守阈值，GitHub 普通 Git 单文件限制为 100 MiB。[GitHub 文档](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)。

## GitHub 连接与同步可靠性

hub init --github OWNER 把账号映射为默认 schedule-workspace URL。用户先创建空私有仓库，Git 负责身份认证；CLI 不处理 OAuth，不读取或保存 API key。--remote 支持自定义 Git 服务。

同步只有显式 push/pull/clone/checkout 时联网，不周期性后台上传。hub push 上传工作空间受管文件，不替所有引用项目 push 源码。本次开发测试用本地 bare 仓库，未为用户创建或上传个人工作空间。

用便携状态指纹做三方比较。原端和新端均修改且不一致时停止，而不是让 Git 文本合并随意拼接数字 ID。镜像只快进，不强制推送。--replace 明确接受远端业务状态，保存前保留 .bak；镜像脏文件和 Git 分叉仍需先处理。

操作失败可用 hub status、project status 和 export 排查。各个 JSON 文件原子写，跨文件和网络动作没有全局事务；网络失败不等于数据已经同步。重试前可以查看远端/本机状态。

## CLI 体验约定

- 默认无参数即总览，短命令 tc。
- 配置、预算、用量都按模型/来源清楚分列，不显示可误用的总余额。
- 人类输出用中文、表格、额度条、四象限、时间区间与每日趋势；--json 输出完整字段。
- 未安排的任务给出能力、额度、依赖或时间原因。
- 默认计划只预览；已有预留保持稳定，rebalance 才重新分配。
- 手动记账第一优先，不要求安装厂商 SDK、获取自动化权限或维护 API 密钥。
- 旧 v1 数据自动读取迁移，旧 tongchou 命令和数据路径保留兼容。
- 订阅停用和模型停用分离；前者仍可使用该模型 API，后者两种来源都不可安排。

完整 [CLI 清单](CLI.md) 和 [数据结构](DATA_MODEL.md) 与源码保持一致。
