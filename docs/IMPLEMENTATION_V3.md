# v0.3 落地设计：逻辑任务与 agent 工作空间分离

状态：已实现，2026-09-21。操作指引见 AGENT_WORKSPACES.md，全部命令见 CLI.md；验证结果见 VALIDATION.md。

## 需求与审查结论

逻辑任务是用户要完成的工作，可手工完成，也可与模型合作。agent 项目是 Codex、ChatGPT 等平台的工作容器；两者是可选的多对多关联，聊天也可关联多个任务。调整 agent 文件结构不改变任务进度、重要性、模型预算或用量。

只同步一个用户自己的 Git 工作空间仓库。登记目录内的持久文件整体纳管，不以“是否像记忆文件”筛选。遇到独立 Git 仓库停止递归，登记引用：有 GitHub/可携带远程地址就记录地址，否则必须有机器身份和本地绝对路径。仓库引用不代表正文已经备份；本地仓库无远程时必须显示不可在其他设备直接还原。原代码仓库里的未推送文件也不会随索引自动同步。

机器使用稳定 ID 和可改的别名；克隆 hub 不克隆当前机器身份。纯本地仓库的位置属于用户要求共享的元信息，允许进入中央 Git；不上传认证信息。一个仓库可有多个机器位置、被多个 agent 项目引用。不能仅凭同名或相同 remote 自动合并项目记忆。

## 存储与权威来源

新 hub 格式为 2（旧版程序拒绝写入），规划 State 继续使用 v2，数学和账本不改。新建 hub 使用新格式；旧 hub 显式迁移，保留备份和旧快照；其他旧设备可快进跟随中央迁移身份。

```
.schedule-hub.json           # 格式与工作空间身份
planning/state.json          # 规划数据的同步副本，独立导入/导出
catalog/agents/<id>.json      # agent 项目、平台来源、任务关联、归档/合并去向
catalog/nodes/<id>.json       # 文件夹/仓库入口/聊天，父节点、项目、任务关联
catalog/repos/<id>.json       # remote、机器位置、旧版来源
catalog/machines/<id>.json    # 机器别名；本机身份另存在本地数据目录
content/<node-id>/            # 该节点直属文件；子目录由子节点组织
```

目录树是逻辑树，节点 ID 保证移动、重命名后正文位置不变。正文为真实可编辑文件，不能被 JSON 中的旧记忆覆盖。每个子目录单独登记，导出时恢复原目录层级和指令作用域。中央按 ID 存储的目录不是可直接替代原执行环境的布局；给 agent 交接使用恢复后的目录或明确的路径索引。

本机配置保存设备 ID、hub 路径、内容选择和来源目录的同步基准。共享配置不把另一台设备的路径当成本机路径。机器别名不等于 SSH 连接能力。

## 生命周期与 Git

支持创建、登记来源、聊天摘要、任务关联、目录移动、重命名、拆分、合并、归档、删除。合并默认把来源项目放入独立分组，保留指令边界、聊天来源与旧项目去向；不自动拼接文档或改动平台服务端项目。仓库复用索引，删除入口不删除原代码。

修改形成普通文件差异，使用 Git 提交、分支、合并和恢复。CLI 验证 ID、父子循环、跨项目父节点、同级大小写冲突、仓库/机器引用、路径可携带性。文本合并成功不等于语义正确。推拉不能强制覆盖分叉；合并先在临时工作树验证，原工作树不因失败被部分更新。账本双边更改不做自动 JSON 合并。

本机多命令互斥锁与 hub 锁同时使用；跨文件内容修改使用事务备份，失败/中断后的下次命令先恢复。业务数据无独立操作日志系统，历史由 Git 保存。

## 文件收集与恢复

首次 import 默认预览，--apply 才纳管；递归读取普通文件，保留目录结构，排除常见构建/缓存/凭据文件及用户规则。尊重目录内 .gitignore / .tcignore；不跨符号链接或目录联接，不越过 .git 边界。纳管非仓库的源目录不需要 git init。

collect 根据上次采集基准比较来源与中央正文。双方不同修改时拒绝覆盖；源目录缺失不推断删除。来源删文件默认保留归档，显式 prune 才传播删除。首次来源映射和后续基准只存在本机。导出只允许新目录，保留仓库入口清单，默认不克隆代码；代码使用 repo checkout 单独获取。本地-only 仓库显示机器位置。

手工增加中央正文会被正常同步；新增目录应登记为节点，避免物理树和目录说明同时成为真相。文本搜索只用于查找，不是同步前置条件。远程平台只保存可取得的来源链接、导出文件和显式摘要，不承诺迁移未开放的内部记忆。

## 同步与按需内容

完整轻量目录常驻；正文可按 agent 项目选择工作树范围。未选择、未下载、来源不可访问、明确删除是不同状态。选择不构成权限隔离。默认 Git clone 下载完整对象；可选 partial clone 只在服务器支持时减少下载，不能把 sparse checkout 宣称为节省传输。

hub 的 agents-only 模式不读写本机规划账本。Git 同步仍涉及当前分支历史，不能宣称推送时能过滤已提交的历史。默认完整同步保留旧有单写端账本冲突检查；结构更改与实际模型使用互不影响。

## 迁移

先备份 v0.2 的 hub 与规划数据。旧 Project 是仓库登记，不自动推断它就是某个平台的 agent 项目：转换为仓库索引，旧 CONTEXT/MEMORY 导入明确标记为待整理的迁移容器，用户可再移动。保留旧 tasks 的 project 文本标签及所有模型/额度/事件/预算/复盘；不猜测多对多关联。旧 bundle 留在 legacy 路径与 Git 历史中，继续可恢复，但新仓库登记不再默认制作代码 bundle。迁移应可预览、可重复检测、不让第二台设备重新生成身份。

## 验收场景

1. 同一逻辑任务关联多个 agent 项目；多个任务关联同一聊天；整理项目后账本逐字不变。
2. 登记无 Git 的混合目录，笔记、脚本、附件进入中央；嵌套仓库只存索引。
3. 本地-only 仓库显示机器别名和路径；机器改名保持身份；新设备不冒用旧机器。
4. GitHub 仓库可增加地址、绑定多设备、被多项目复用，不复制代码。
5. 两个设备经本地 bare remote 完整往返，直接修改中央文档可保留，目录树导出正确。
6. 移动、拆分、合并、删除不会影响源文件、代码仓库或模型额度；合并指令保留分组。
7. 来源缺失/删除、双边修改、未选择正文不会被静默覆盖或丢弃。
8. 分支合并有文本冲突或结构冲突时停止，原主工作树不变。
9. 迁移保留全部旧版任务、预算、用量、记忆和 bundle；旧 writer 拒绝新 hub。
10. Windows/Linux/macOS 路径规则、中文、空格、同级大小写冲突、符号链接与 Git 边界。

## 实施范围

先交付可用的目录管理、仓库/机器索引、正文采集恢复、Git 同步、迁移和验证。自动接管云端聊天、后台同步、全文向量检索、预测用量、自动跨主机复制本地-only 代码均不是本版隐含能力。

## 最终实现说明

- 项目删除采用归档隐藏，正文保留；节点子树可显式 remove。来源项目合并后保留归档身份和去向。
- 按需正文支持 agent 项目或单独节点子树，正文搜索仅对已检出的 UTF-8 文件（至多 2 MiB）进行；不调用模型。
- export 恢复目录树，但不隐式克隆代码；仓库清单在 .tc-export.json。加 --bind 才作为本机后续 collect 来源。
- 保存的是普通文件正文和目录结构，不迁移特殊权限、ACL 或扩展属性。
- State schema 仍为 2，hub 格式从 1 升级到 2，CLI 版本为 0.3.0。三者独立。
- 尚无旧 hub 的 v0.2 用户第一次 hub init 时转换已有仓库/记忆登记；已有旧 hub 则显式 migrate 后由其他设备跟随中央身份。
